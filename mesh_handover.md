# Auto-Mesh handover: shell-first hybrid meshing (SFHM)

Last updated 15 Nov 2026. Goal: open-source mesher that beats snappyHexMesh and commercial meshers on head-to-head metrics. Companion docs: `README.md` (ML sizing / y+ spec side), `RESEARCH_volume_meshing_v1.md` (literature, method, debate, 2D results, variable-thickness options), `proto2d/README.md` (how to run).

## 1. One-paragraph summary

Every production mesher (Mosaic, STAR trimmer, Hexpress, T-Rex, snappy, cfMesh) builds the boundary layer outward from the wall and then fights collisions, collapses and transition cells. SFHM reverses the order: build the boundary-layer *outer shell* first as a guaranteed offset of the wall, mesh the bulk against that smooth shell (where grid-based hex meshing has a Jacobian proof, MCHex 2026), then fill the layers by tracing harmonic streamlines from the shell down to the wall. Geometry is ingested implicitly (winding-number signed distance), so dirty STL needs no wrapper. A 2D prototype exists and beats snappyHexMesh on the same spec. Self-assessed novelty 7/10 (details in research doc section 5).

  - winding-number SDF from polyline soup (orientation agnostic, bridges holes)
  - variable thickness δ(s) via warped level set + Lipschitz envelope + angle-based gap clipping (`--variable`)

  - Laplace fill in the shell, streamline tracing, geometric layer growth, exact wall + feature snapping

  - direct OpenFOAM polyMesh writer (1-cell extrusion) + `system/` dicts

### Known defects / limitations of v1
- (fixed in v4) zero-width sliver / fold / hole in the dirty case.
- (fixed in v3) first cell thinner than spec where δ is clipped.
- (fixed in v2) shell was option A; now eikonal. FMM runs on the uniform local grid, not the quadtree (fine in 2D; 3D needs octree FMM / FIM).
- Concave cells (350/604/428 on airfoil/square/two-element, ~1.7–5× snappy) come from bulk cut-cell polygons, not the shell; unchanged in v2.
- With variable δ the eikonal shell can sit up to 2.3·δ_eff where δ is clipped (front from neighbouring segments); step 2 handles the layer side.
- Gaps narrower than 2·δ_min: shell vanishes, no fill (needs the medial-ridge two-sided fill).
- Cut-cell polygons can still be thin after snapping (checkMesh "small interpolation weight" warnings, 2–8 faces per case).
- Pure Python, 4–14 s per 2D case; winding evaluation and streamline tracing dominate.
- snappy wall-clock not comparable (3D slab, no 2D mode); only cell count and quality were compared.

## 4. Decisions and conventions
- The neural network never builds the mesh; it only sets sizing, thickness, layer count and the mode gate.
- Shell-first order is the core idea; keep it even if individual components (MCHex vs dual-octree, Laplace vs eikonal fill) are swapped.
- Cell count comparisons are made at equal wall spacing and equal layer spec; timing comparisons only against 3D meshers in 3D.
- Convex features are handled combinatorially (fans), never by smoothing.
- New script versions get new filenames (`*_v2.py`); v1 results in `proto2d/runs/` are the baseline.
